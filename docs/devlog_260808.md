## 운영 작업

### 1. 전체 회차 데이터 최신화

- 동행복권 공식 API 기준으로 DB를 보정했다.
- 로또: `1~1235회`, 총 `1,235건`
- 연금복권: `1~327회`, 총 `327건`
- 두 테이블 모두 `1회~최신회` 사이 누락 회차 `0건`을 확인했다.

### 2. 다음 회차 추천 및 Telegram 발송

- 로또 `1236회`: 통계 3게임 + AI 경로 2게임 저장 및 발송
- 연금복권 `328회`: 동일 6자리 번호를 1~5조로 구성한 5게임 저장 및 발송
- 두 Telegram API 응답 모두 `sent: true` 확인
- 당시 Ollama 호출이 실패해 로또 AI 경로 2게임은 기존 랜덤 fallback으로 생성됐다.

## 코드 리뷰 결과

### 이번에 처리한 항목

1. **연금복권 등수 계산 오류**
   - 기존에는 끝 5자리 일치를 2등으로 계산했다.
   - 6자리 동일·조 불일치를 2등, 끝 5~1자리 일치를 3~7등으로 수정했다.

2. **결과 재처리 불가 문제**
   - 채점 결과가 이미 DB에 있으면 응답 결과에서 제외되어 Telegram 재발송이 불가능했다.
   - 기존 결과도 응답에 포함해 전송 실패 후 재시도할 수 있도록 수정했다.

3. **연금 추천 부분 저장 가능성**
   - 5게임을 한 건씩 저장하던 코드를 일괄 저장으로 변경했다.

4. **동행복권 API 장애 오판**
   - 연금 최신 회차 조회 실패를 1회차로 오판하던 동작을 제거했다.
   - 로또/연금 API 요청에 15초 타임아웃을 추가했다.
   - 로또 API 빈 응답을 명시적으로 검증한다.

## 후속 구현: 중복 방지와 당첨 알림

### 중복 추천 및 발송 방지

- 로또·연금 추천에 `(target_draw_id, game_number)` 고유 인덱스를 추가했다.
- 기존 중복 추천 65건은 결과가 연결된 행을 우선 보존하고 정리했다.
- 추천 생성은 이미 완성된 5게임이 있으면 그대로 반환하며, 불완전한 세트는 오류로 처리한다.
- Telegram 발송 이력을 `notification_deliveries`에 기록해 회차·이벤트별 중복 발송을 막고 실패/장기 대기 건만 재시도한다.
- 마이그레이션 적용 전 백업: `.tmp/lottochu-before-idempotency-20260808.backup`

### 연금복권 보너스 번호와 축하 알림

- 공식 API의 보너스 6자리를 `pension_draws.bonus_digits`에 저장한다.
- 1~327회 전체를 재동기화해 보너스 번호 327건이 모두 채워졌음을 확인했다.
- 보너스 번호 일치 시 8등으로 판정하고, 기존 결과도 최신 당첨 정보에 맞춰 재계산한다.
- 로또·연금 결과 메시지를 고액 당첨/일반 당첨/낙첨으로 구분한다.
- 당첨 게임 수, 최고 등수, 예상 당첨금 또는 연금 지급 방식, 공식 확인·복권 보관 안내를 추가했다.
- 마이그레이션 적용 전 백업: `.tmp/lottochu-before-winning-notification-20260808.backup`

## 24시간 운영 권장안

현재 PostgreSQL과 Ollama를 유지하려면 Ubuntu VPS 1대에 Docker Compose로 아래 서비스를 운영하는 구성이 가장 단순하다.

- NestJS API/Scheduler
- PostgreSQL 영구 볼륨
- Ollama 및 모델 영구 볼륨
- 컨테이너 자동 재시작
- 외부 DB 백업
- API 비공개 또는 관리자 인증 적용

Ollama까지 같은 서버에서 실행할 경우 8GB RAM 이상을 권장한다. 비용을 낮추려면 Ollama를 외부 AI API로 교체하고 API와 PostgreSQL만 PaaS에 배포하는 대안도 가능하다.
